# Runtime object serialization

## Problem and design reasoning

A live object graph contains shared references, cycles, borrowed resources, and callbacks. Copying each reachable object recursively can duplicate shared objects or restore references before their targets exist. In shipped Factorio, the mod storage contract explicitly supports circular table references and references to engine LuaObjects. Registered metatables are relinked by name, while functions cannot be persisted. Those are deliberate boundaries between serializable state and executable behavior. [Wube, Factorio storage contract](https://lua-api.factorio.com/latest/auxiliary/storage.html)

Chris Butcher's GDC 2015 talk describes reflection and source-content formats as foundations of Destiny's engine evolution. It illustrates how object description connects runtime systems and authoring tools. The graph protocol below is a portable recommendation, rather than an attribution of that protocol to Bungie. Its purpose is to make identity and ownership survive reconstruction without letting transient services leak into the serialized graph. [Bungie, Lessons from the Core Engine Architecture of Destiny, GDC 2015](https://media.gdcvault.com/gdc2015/presentations/Butcher_DestinyEngine_GDC2015_final.pdf)

## Techniques and practical checks

- **Describe edge ownership.** Classify fields as owned child objects, shared object references, external resource handles, or transient runtime bindings. Assign one serialized identity to each included object and record references using that identity. Define what happens when an external object cannot be resolved. **Check** a fixture where two objects share a child, a child points back to its parent, and one field refers to an unloaded asset. Restore it and verify identity sharing, the cycle, and the documented unresolved-resource result.
- **Construct before fixing references.** Allocate the object shells from validated type records, fill their values, and resolve graph edges in a later pass. Keep constructors used for loading free of observable gameplay side effects until publication. **Check** shuffle record order and include a forward reference, duplicate identity, unknown type, and absent target. Verify valid graphs restore equivalently and invalid ones produce a precise failure before gameplay sees the objects.
- **Rebind transient behavior at a controlled boundary.** Recreate subscriptions, callbacks, and service connections from restored state after graph validation. Give one owner responsibility for this activation and for cleanup if activation fails. **Check** a graph containing listeners and timers. Restore twice into separate test sessions and verify each listener attaches once, expired work stays expired, and a failed activation releases partial bindings.
- **Preserve the old world until replacement succeeds.** Reconstruct into a temporary ownership scope and validate references before replacing live roots. Dispose the temporary scope on failure and retire the previous graph only after the handoff is complete. **Check** inject failure during allocation, reference resolution, and activation. Confirm the old graph remains usable where the operation promises transactional replacement and no temporary objects remain reachable.
