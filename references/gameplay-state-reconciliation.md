# Gameplay state reconciliation

## Problem and design reasoning

Local prediction keeps interaction responsive, but the predicted timeline may differ from the server's confirmed state. Reconciliation retargets that local timeline to confirmed state and replays still-pending input. In *Rocket League*, Psyonix describes recording local input and comparing server physics state with client history, reverting and replaying when the difference warrants correction. In *Overwatch*, Blizzard describes using determinism in a networked simulation to support responsive and precise gameplay. A design inference is to choose the replays, resets, and visual correction policies based on which errors affect player decisions. [Jared Cone, It IS Rocket Science!, GDC 2018](https://media.gdcvault.com/gdc2018/presentations/Cone_Jared_It_Is_Rocket.pdf) · [Timothy Ford, Overwatch Gameplay Architecture and Netcode, GDC 2017](https://gdcvault.com/play/1024001/contactUs)

## Techniques and practical checks

- **Align snapshots and input acknowledgments.** Tag predicted history with the simulation tick or input sequence it represents. Accept a newer authoritative state in its correct session and timeline, then replay only unresolved inputs in order. **Check** an out-of-order snapshot, a repeated acknowledgment, and several pending inputs. Compare the restored tick and final state with the expected timeline.
- **Restore all state required by the replay.** Include the relevant velocity, timers, cooldowns, and state transitions, plus any coupled simulation inputs needed for the replay window. If the required history is gone, define a bounded reset path. **Check** correct a tick just before landing or entering a new ability state. Then deliver a correction older than retained history and inspect whether reset converges without leaving stale prediction state.
- **Separate simulation correction from presentation.** Apply authoritative simulation state at the correction boundary. Smooth eligible visual offsets independently, and snap for discontinuities such as teleports or respawns. **Check** impose a small correction, a large correction, and a teleport. Verify collision follows corrected state immediately and visible error decays or snaps according to policy.
- **Keep replayed effects idempotent.** Resimulation writes simulation state repeatedly. Associate predicted and confirmed feedback with a stable event identity and consume rewards through the confirmed path. **Check** repeat a correction over the same action under packet loss and jitter. Count audiovisual effects, resource changes, and reward grants to verify the intended once-only behavior.
