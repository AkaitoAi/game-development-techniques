# Runtime socket validation

## Problem and design reasoning

A model can import successfully while an attachment appears mirrored, floats away in motion, or loses its expected anchor at a lower detail level. Those defects often originate in names, axes, units, or exported hierarchy changes. In released *Quake III Arena* code, the torso is positioned on the legs' `tag_torso`, with its own animation representation. The anchor is a content contract consumed by runtime code. [id Software, player model assembly](https://github.com/id-Software/Quake-III-Arena/blob/master/code/cgame/cg_players.c)

Naughty Dog's *Uncharted 2* character pipeline presentation documents using referenced authoring assets to maintain one skeleton across outfits. Consistent rig structure reduces the number of compatibility cases artists must maintain. The socket manifest and fixture below are portable recommendations inferred from these integration needs. The talk does not establish that Naughty Dog used this exact validator. [Richard Diamant and Judd Simantov, Uncharted 2 Character Pipeline, GDC 2010](https://www.gdcvault.com/play/1012798/Uncharted-2-Character-Pipeline-An)

## Techniques and practical checks

- **Declare the exported contract.** For each asset family, record required socket identifiers, semantic axes, local unit scale, permitted parents, and optional fallback anchors. Validate the exported hierarchy rather than relying on its appearance in the authoring tool. A duplicate name should resolve according to an explicit path rule or fail with an asset location. **Check** import a fixture with a missing socket, duplicated socket name, rotated root, and unit mismatch. Verify that each failure identifies the offending asset and contract field before normal gameplay activates it.
- **Use reference attachment fixtures.** Build lightweight axes and representative item silhouettes at the authored anchor. Define acceptable positional and angular tolerances for each gameplay pose. Keep corrections in one owned location, such as a socket transform or an item-specific offset, so a reimport cannot accidentally apply the same correction twice. **Check** equip the fixture on supported body variants, then run aim, crouch, reload, and full-body interactions. Record attachment error in world units and degrees, and inspect the silhouette from the gameplay camera.
- **Validate representation changes.** Decide which anchors remain available across skeleton reduction, LOD swaps, or first-person and third-person representations. A fallback should preserve the intended semantic position and have a documented quality limit. **Check** cross every representation threshold while an attachment is visible and while a secondary effect uses its socket. Confirm that anchor lookup remains valid and that no item or effect snaps to the actor root.
- **Version and invalidate socket mappings.** Cache lookups against a rig or asset revision. Re-resolve them after replacement or reload, and verify that pending attachment work still targets the same owner and compatible rig. **Check** rename a socket through the supported migration path, reimport the rig, and deliver a delayed equip completion from the previous revision. Confirm the old mapping cannot be applied and the failure produces an actionable diagnostic.
