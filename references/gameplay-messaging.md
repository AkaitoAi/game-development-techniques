# Gameplay messaging and event delivery

## Problem and design reasoning

One game action can change simulation state and affect several independent consumers. When equipment, tutorials, UI, and audio poll for the same change or call one another directly, it becomes hard to tell which system owns the outcome. Valve's published Source SDK for shipped titles such as *Half-Life 2* exposes named game events and listener registration, including a distinction between local events and events that can be transmitted. Wube exposes selected *Factorio* runtime events to mods with a tick and event-specific payload, and some support filtering to avoid unnecessary callbacks. Blizzard's developer talk on *Overwatch* describes automating prediction and replication for scripted behaviors so designers can iterate without handling each networking case independently. An implementation inference is to make audience and delivery semantics part of the messaging contract. ## Techniques and practical checks

- **Give mutation a known owner.** Route a request such as `EquipItem` to the inventory owner. After validation and mutation, publish a fact such as `EquipmentChanged` for interested consumers. Use a direct call when the caller must wait for one definitive answer. **Check** rejected and successful commands back to back. Verify that rejected commands leave inventory unchanged and that observers receive exactly one fact for each committed change.
- **Choose the event scope and delivery point.** Scope gameplay events to the appropriate entity, scene, or match. Queue events at a named simulation boundary when synchronous callbacks would interrupt an update. Assign deterministic priority or sequencing if ordering affects game state. **Check** two related facts arriving in the same tick, including a listener that issues a follow-up command. Verify the intended sequence both at runtime and on replay where supported.
- **Distinguish predicted presentation from confirmed outcomes.** Use stable action identities and source ticks where events are replayed or reconciled. Make irreversible consumers act on the authoritative result and make confirmed delivery safe to repeat. **Check** a prediction that is rejected, one that is confirmed, and a confirmation delivered twice. Verify cosmetics reconcile and each authoritative grant occurs once.
- **Own subscription lifetime and debugging.** Return a subscription handle or bind it to an explicit lifetime, including for pooled objects. Provide a trace of publisher, event identity, delivery phase, and consumer. **Check** unloading a scene, disabling a widget, and recycling a subscribed entity. Send the same event after each transition and verify the active recipients and explainable trace.
