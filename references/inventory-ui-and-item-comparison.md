# Inventory UI and item comparison

## Problem and design reasoning

Players need to find items quickly and know what changes when they equip or move one. Detailed stats can slow routine decisions, but a simplified score can hide the effects that matter for a particular build. Blizzard documented how broad Diablo III summaries became misleading and were refined. Bungie's Destiny interface talk explains how a free cursor and tooltips made a dense gear screen faster to navigate. A design inference is to keep summaries useful for scanning and let players inspect the assumptions and detailed effects before committing. [Blizzard’s item comparison retrospective](https://news.blizzard.com/en-us/article/20120910/diablo-then-now-item-comparison-evolution) · [David Candland’s Destiny UI slides, GDC 2016](https://media.gdcvault.com/gdc2016/Presentations/Candland_David_Tenacious_Design_and.pdf)

## Shipped examples and developer talks

| Game | Shipped approach |
|---|---|
| **Destiny** | The character interface places equipment around the character and lets controller users move a free cursor between slots. Bungie used the cursor and tooltips to present dense information and reduce repeated directional presses between distant targets. [Tenacious Design and The Interface of Destiny, GDC 2016](https://gdcvault.com/play/1023460/Tenacious-Design-and-The-Interface) · [Annotated presentation slides](https://media.gdcvault.com/gdc2016/Presentations/Candland_David_Tenacious_Design_and.pdf) |
| **Diablo III** | Blizzard revised its comparison summaries over multiple patches. Toughness combined survivability components, while healing effects with variable triggers made early numerical summaries difficult to interpret. The retrospective documents the limits of collapsing distinct effects into a headline figure. [Blizzard’s item comparison retrospective](https://news.blizzard.com/en-us/article/20120910/diablo-then-now-item-comparison-evolution) |
| **Destiny 2** | Bungie distinguishes items held on a character, vault storage, and missed pickups sent to the Postmaster. Its documentation describes sorting and warns that items in the Postmaster can be lost. These containers need distinct status and capacity cues. [Bungie’s inventory documentation](https://help.bungie.net/hc/en-us/articles/360049199931-Destiny-2-Inventory-Management-Postmaster-Vault-and-Character-Inventory) |

## Techniques and practical checks

- **Preserve focus by item identity.** Use a stable instance ID for focused and pinned items so a reorder cannot silently change the selection. Define where focus goes when the item disappears, and keep essential actions reachable with supported inputs. **Check** a gamepad workflow from finding an item through equipping and returning to the list. Repeat while items arrive, filters change, and the selected item is removed. Confirm every destructive or equip action acts on the visible target.
- **Compare complete before-and-after loadouts.** Evaluate the same stat rules on the current loadout and a projected valid replacement. Show which slots change and flag effects whose value depends on combat context. **Check** dual wield, two-handed replacement, set-count thresholds, equipment prerequisites, and a conditional modifier. Commit each valid swap in a test build and compare reported stat changes with what gameplay computes.
- **Pair concise deltas with details.** Show a short summary for scanning and align matching properties in a detailed view. Use labels and symbols alongside color and explain units, caps, and conditional effects. **Check** long localized strings, narrow viewports, large text, and monochrome contrast. Ask a player to identify a situational sidegrade and explain which effect makes it useful.
- **Make container actions predictable.** Label the destination, available space, merge amount, and any consequence before actions that consume or discard items. Keep failed operations visible and refresh the view from the confirmed inventory state. **Check** moving into a full container, splitting a stack, attempting to dismantle a protected item, and receiving a delayed response. Verify the UI shows the correct remaining count and gives a recovery action when the move fails.
