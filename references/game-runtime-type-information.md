# Game runtime type information

## Problem and design reasoning

Editors, serializers, and debug inspectors need to identify the fields of an object without each system maintaining a separate description. Valve's released Source SDK declares typed fields, map keys, inputs, and outputs in data descriptions. Its Half-Life 2 code shows how engine systems can inspect those declarations. Chris Butcher's GDC 2015 presentation identifies reflection as a core part of the shipped Destiny engine and explains that core systems share assumptions about formats and object lifetimes. The design inference is to make schema ownership explicit before several tools depend on it. [Valve, Source data descriptions](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/server/logicentities.cpp) · [Bungie, Lessons from the Core Engine Architecture of Destiny, GDC 2015](https://media.gdcvault.com/gdc2015/presentations/Butcher_DestinyEngine_GDC2015_final.pdf)

## Techniques and practical checks

- **Register capabilities with field metadata.** Give each reflected type a stable identifier, field identifiers, field kinds, and explicit eligibility for editing, serialization, or inspection. Keep transient runtime members outside persistence unless their restoration is defined. **Check** a fixture with inherited fields, arrays, references, and transient state. Confirm each consumer sees the intended members and rejects unsupported field kinds.
- **Generate or validate schemas from one owner.** Make code generation or registration checks report duplicate IDs and missing registrations before content is published. Provide readable names for diagnostics while keeping persisted identity stable across renames. **Check** rename a field, add a type, and deliberately duplicate an ID. Verify that existing data either migrates as specified or fails with the exact offending type and field.
- **Resolve references through lifetime-aware APIs.** Let metadata describe a reference kind while the object system owns resolution, validity, and destruction. Avoid storing raw offsets or pointers in portable data. **Check** inspect and serialize a reference after its target is destroyed, replaced, or unloaded. Verify a defined missing-reference result and no access to recycled objects.
- **Measure reflective work at its actual call rate.** Use direct or compiled accessors for frequently visited fields where profiling justifies them, and keep editor-only metadata out of builds where it is unnecessary. **Check** representative inspect, save, and load workloads, then a dense runtime query. Report total cost and allocations and confirm optimized access produces the same values.
