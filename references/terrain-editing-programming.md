# Terrain editing programming

## Problem and design reasoning

Terrain edits can update density data before the visible surface, collision, and saved state have caught up. A late generation job can then overwrite a newer edit or publish a surface whose neighboring chunk uses a different border. In *No Man's Sky*, Innes McKendrick described the continuous pipeline from voxel generation through polygonization to population and simulation. This supports treating derived terrain representations as a pipeline with dependencies. It does not establish that the game uses the revision protocol recommended below. [Hello Games, Continuous World Generation in No Man's Sky, GDC 2017](https://www.gdcvault.com/play/1024265/Continuous-World-Generation-in-Noby)

System Era's *Astroneer* talk describes free-form terrain sculpting as part of the game's design. Its shipped update 1.26 fixed items phasing through cave layers after the affected terrain left relevance. These are concrete reasons to test terrain edits across simulation and streaming boundaries. The programming approach below is an engine-independent inference from those failure modes. [Aaron Biddlecom, Mining Your Own Design, GDC Summer 2020](https://media.gdcvault.com/gdcsummer2020/presentations/Biddlecom-Aaron-MiningYourOwnDesign.pdf) · [System Era, update 1.26](https://blog.astroneer.space/p/update-1-26/)

## Techniques and practical checks

- **Version the edit source.** Give each terrain region a monotonically increasing revision and generate derived data from an immutable input snapshot. Return the region ID, generation, and revision with each result. **Check** hold the first mesh job, make a second edit, publish its result, then release the first job. Verify the old result is discarded and cannot replace the newer surface.
- **Invalidate shared borders explicitly.** Include the sampling halo required by the meshing algorithm and mark all dependent neighbors dirty when a boundary changes. Use the same border source revision or a documented seam policy. **Check** excavate across a chunk corner while neighboring jobs finish in different orders. Inspect for cracks, duplicate faces, and collision gaps.
- **Publish an explicit playable revision.** Define which mesh, collider, navigation data, and attachment information must agree before the edited region is usable. If visual and physical publication differ, expose the pending state or maintain a safe temporary interaction rule. **Check** dig beneath a player and a supported prop during a long collision rebuild. Verify the published revision and the intended support or falling behavior.
- **Persist edits with stable identity.** Store edit operations or compact terrain deltas against a known base-content version and region coordinate. Keep unloaded region changes authoritative across rebuilds. **Check** edit, unload, save, restart, and revisit in a different order. Compare source terrain and derived borders with the uninterrupted run.
