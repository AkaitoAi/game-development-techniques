# Game transform hierarchies

## Problem and design reasoning

An object may follow a vehicle, bone, or animated socket and later need to detach without jumping. Storing local transforms and deriving world transforms in dependency order makes that relationship explicit. Physics and network ownership are separate relationships. Define which transforms inherit position, rotation, or scale and when other systems may read their resolved values.

In the released *Quake III Arena* client code, id Software attaches the player torso to a tag on the legs and the head to a tag on the torso. The positioning helpers sample an animated tag and combine it with the parent transform. In Naughty Dog's *Motion Matching in The Last of Us Part II* GDC talk, an authored root reference drives the capsule and provides a shared frame for joint evaluation. These shipped cases document distinct ways to compose local attachment data with a parent frame. An implementation inference is to keep a named socket or root-frame contract at subsystem boundaries so consumers can identify both the source and its update phase. [id Software, player attachment code](https://github.com/id-Software/Quake-III-Arena/blob/master/code/cgame/cg_players.c) · [id Software, tag positioning helpers](https://github.com/id-Software/Quake-III-Arena/blob/master/code/cgame/cg_ents.c) · [Michal Mach and Maksym Zhuravlov, GDC slides](https://media.gdcvault.com/GDC%2B2021/Motion_Matching_In_TLOU2.pdf)

## Implementation and checks

1. State the space convention. With column vectors, compute `ChildWorld = ParentWorld * ChildLocal`. Compose a socket in its owner's frame before applying the attachment offset, and keep points, directions, and normals distinct where scale applies. **Check** a three-deep chain with rotated parents and a nonzero socket offset. Compare resolved axes and positions against values calculated independently.
2. Preserve the intended pose during reparenting. For a keep-world operation with an invertible parent, compute `NewLocal = inverse(NewParentWorld) * OldWorld`. Use a separate keep-local operation when attaching at an authored offset. Set a policy for singular transforms and affine results with shear that a translation-rotation-scale representation cannot preserve exactly. **Check** reparent and detach a child under uniform and nonuniform scale. Verify the supported case preserves world pose and the unsupported case reports or handles the loss deliberately.
3. Evaluate transforms before publishing them. Order local writes, animation pose evaluation, hierarchy propagation, and dependent reads according to the scene's dependencies. Track parent changes and invalidate affected descendants even when their local values are unchanged. **Check** move a parent and animate a socket in the same tick. Inspect attachments, collision queries, and rendering for a one-frame lag, including after a paused frame.
4. Validate structural changes and ownership. Reject cycles, decide what happens to surviving children when a parent is destroyed, and explicitly transfer dynamic bodies between physics ownership and attachment ownership where the game requires it. **Check** attempt a cycle, remove a parent during traversal, then attach and detach an object on a moving platform. Verify deterministic ordering, a valid resulting hierarchy, and continuity of any inherited velocity promised by the gameplay rules.
